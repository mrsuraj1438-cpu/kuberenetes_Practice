Day 26 – GitHub CLI (gh) Notes (Part 1)

GitHub CLI: Manage GitHub from Your Terminal

What is GitHub CLI?

GitHub CLI (gh) is the official command-line tool developed by GitHub that allows you to interact with GitHub directly from your terminal.

Instead of opening the GitHub website to create repositories, issues, pull requests, or run workflows, you can do everything from the command line.

Why Use GitHub CLI?

  • Faster than using the GitHub website.
  • Ideal for DevOps automation.
  • Integrates easily with shell scripts and CI/CD pipelines.
  • Helps manage repositories, pull requests, issues, releases, and GitHub Actions from one place.

Installation

Ubuntu

sudo apt update
sudo apt install gh

Verify Installation

gh --version

Example:

gh version 2.xx.x
https://github.com/cli/cli/releases

Authentication

Login

gh auth login

Choose:

GitHub.com
SSH
Login with a web browser

Check Login Status

gh auth status

Example:

github.com

✓ Logged in to github.com account alank8s-cloud-code

Active account: true
Git operations protocol: ssh
Token scopes:
repo
gist
read:org

View Your Token Scopes

gh auth status

or

gh auth status -t

Note: -t displays the token. Avoid using it when sharing your screen or terminal because the token is sensitive.

Add More Permissions

Example: Add permission to delete repositories.

gh auth refresh -h github.com -s delete_repo

Meaning

Option Meaning
gh auth refresh Update your existing authentication
-h github.com GitHub host
-s delete_repo Request the delete_repo permission

Protect Your GitHub Token

  • Never upload your token to GitHub.
  • Never share screenshots showing the token.
  • Avoid using gh auth status -t during presentations or recordings.
  • Store tokens securely.
  • Revoke tokens immediately if they are exposed.

Repository Management

Create a Repository

Syntax

gh repo create <repository-name>

Example

gh repo create my_portfolio --public --clone --add-readme

Options

Option Meaning
--public Public repository
--private Private repository
--clone Clone immediately after creation
--add-readme Create a README.md

Clone a Repository

What is gh repo clone?

It downloads a GitHub repository to your local computer.

Syntax

gh repo clone OWNER/REPOSITORY

Example

gh repo clone alank8s-cloud-code/my_portfolio

GitHub CLI automatically knows:

  • Repository owner
  • Clone URL
  • Authentication method

Equivalent Git command:

git clone git@github.com:alank8s-cloud-code/my_portfolio.git

List Your Repositories

gh repo list

Limit the number of results:

gh repo list --limit 10

View Repository Details

gh repo view alank8s-cloud-code/my_portfolio

Useful JSON output:

gh repo view alank8s-cloud-code/my_portfolio \
--json name,description,isPrivate,defaultBranchRef

Open Repository in Browser

gh repo view alank8s-cloud-code/my_portfolio --web

WSL Error

Sometimes you may see:

xdg-open: no method available for opening ...

Reason

WSL doesn’t have a Linux web browser installed.

Solution

Copy the URL and open it in your Windows browser, or configure WSL to launch Windows applications.

Delete a Repository

gh repo delete OWNER/REPOSITORY

Example:

gh repo delete alank8s-cloud-code/practice

Skip the confirmation prompt:

gh repo delete alank8s-cloud-code/practice --yes

Common Error

HTTP 403:
Must have admin rights to Repository.

Reason

Your token does not include the delete_repo scope.

Fix

gh auth refresh -h github.com -s delete_repo

GitHub Issues & Pull Requests

GitHub Issues

What is an Issue?

A GitHub Issue is used to track bugs, feature requests, tasks, or improvements in a repository.

Instead of discussing work in chats or emails, teams create issues so everyone can track progress.

Real DevOps Example

A monitoring pipeline fails because the README instructions are outdated.

Instead of sending a message in Slack, create an issue:

Title:
Fix README formatting

Body:
The README contains formatting errors that need to be corrected.

Label:
documentation

Create an Issue

Syntax

gh issue create --repo OWNER/REPO

Example

gh issue create \
--repo alank8s-cloud-code/my_portfolio \
--title "Fix README formatting" \
--body "The README contains formatting errors that need to be corrected." \
--label "documentation"

Output:

https://github.com/alank8s-cloud-code/my_portfolio/issues/1

Verify the Issue

Method 1

gh issue list --repo alank8s-cloud-code/my_portfolio

Example:

#1 Fix README formatting

Method 2

gh issue view 1 \
--repo alank8s-cloud-code/my_portfolio

Method 3

Open the issue in your browser.

gh issue view 1 \
--repo alank8s-cloud-code/my_portfolio \
--web

List Open Issues

gh issue list \
--repo alank8s-cloud-code/my_portfolio

Close an Issue

gh issue close 1 \
--repo alank8s-cloud-code/my_portfolio

Reopen an Issue

gh issue reopen 1 \
--repo alank8s-cloud-code/my_portfolio

Common Error

HTTP 401: Bad credentials

Reason:

The GitHub token is invalid or missing.

Fix:

gh auth login

or

gh auth refresh

Automating Issues

Create an issue from a Bash script:

#!/bin/bash

gh issue create \
--repo alank8s-cloud-code/my_portfolio \
--title "Daily Backup Failed" \
--body "The backup job failed during nightly execution." \
--label "bug"

Example use cases:

  • Backup failures
  • Server outages
  • Disk space alerts
  • Security scan findings
  • Deployment failures

A Pull Request (PR) is a request to merge changes from one branch into another.

Usually:

Step 1: Create a Branch

git checkout -b feature/update-readme

Step 2: Make Changes

Example:

nano README.md

git add .

git commit -m "Update README with GitHub CLI example"

gh pr create \

Understanding Base and Head

Head Branch
feature/update-readme

Base Branch
main

}

Merge Pull Request

Merge commit:

Squash merge:

Rebase merge:

Interview Questions

Q1. What is the difference between an Issue and a Pull Request?

Answer:

An Issue is used to track work such as bugs, feature requests, or tasks. A Pull Request is used to propose code changes and request that they be reviewed and merged into another branch.

Q2. What merge strategies does GitHub support?

Answer:

  • Merge Commit (--merge)
  • Squash Merge (--squash)
  • Rebase Merge (--rebase)

Q3. How do you review someone else’s Pull Request?

Answer:

  1. List pull requests with gh pr list.
  2. View the PR using gh pr view.
  3. Check out the branch with gh pr checkout.
  4. Review the changes using gh pr diff.
  5. Approve, comment, or request changes using gh pr review.

GitHub Actions Workflows with GitHub CLI

What is GitHub Actions?

GitHub Actions is GitHub’s built-in CI/CD platform.

It allows you to automate tasks such as:

  • Building applications
  • Running tests
  • Deploying applications
  • Running scheduled jobs
  • Automating DevOps workflows

These automations are defined in workflow files.

What is a Workflow?

A workflow is a YAML file stored in:

.github/workflows/

Example:

.github/workflows/ci.yml

Example Workflow

name: My First Workflow

on:
  push:

jobs:
  hello:
    runs-on: ubuntu-latest

    steps:
      - run: echo "Hello GitHub Actions!"

Workflow Lifecycle

Workflow File
      │
      ▼
GitHub Detects Trigger
      │
      ▼
Creates Workflow Run
      │
      ▼
Creates Jobs
      │
      ▼
Runs Steps
      │
      ▼
Completed

List Workflows

Syntax

gh workflow list

Example:

gh workflow list

Output:

NAME                      STATE   ID
My first github workflow  active  324404139
Manual Trigger            active  329134277
Matrix Workflow           active  329151867
Pull request Demo         active  329109724
Scheduled Trigger         active  329134278

View Workflow Details

By Name

gh workflow view "Matrix Workflow"

By ID

gh workflow view 329151867

View Workflow YAML

gh workflow view "Matrix Workflow" --yaml

Example:

name: Matrix Workflow

on:
  workflow_dispatch:
    inputs:
      environment:
        required: true
        type: choice
        options:
          - testing
          - deploy

This command is extremely useful when you forget:

  • workflow inputs
  • triggers
  • workflow name
  • jobs

Trigger a Workflow

Syntax

gh workflow run <workflow-name>

or

gh workflow run <workflow-file>

Example

gh workflow run "Matrix Workflow"

Manual Trigger Requirement

A workflow must contain:

on:
  workflow_dispatch:

Without it, GitHub cannot start the workflow manually.

Trigger with Inputs

Your workflow:

on:
  workflow_dispatch:
    inputs:
      environment:
        required: true
        type: choice
        options:
          - testing
          - deploy

Run:

gh workflow run "Matrix Workflow" \
-f environment=testing

or

gh workflow run "Matrix Workflow" \
-f environment=deploy

Common Error

HTTP 422

Required input 'environment' not provided

Reason:

A required workflow input is missing.

Fix:

gh workflow run "Matrix Workflow" \
-f environment=testing

Another Common Error

Provided value 'testing'
not in the list of allowed values

Reason:

The workflow only accepts specific values.

Example:

options:
  - dev
  - staging

Using:

-f environment=testing

will fail.

Use:

-f environment=dev

instead.

Run Workflow by File

Instead of the workflow name:

gh workflow run matrix.yml \
-f environment=testing

Run Workflow by ID

gh workflow run 329151867 \
-f environment=testing

Verify Workflow Started

gh run list

Example:

STATUS        WORKFLOW
queued        Matrix Workflow

or

in_progress   Matrix Workflow

Real DevOps Example

A DevOps engineer needs to run a deployment manually.

Workflow:

workflow_dispatch:
  inputs:
    environment:
      options:
        - testing
        - production

Run:

gh workflow run deploy.yml \
-f environment=production

No need to open GitHub.

Deployment starts immediately.

Workflow vs Workflow Run

Workflow:

.github/workflows/deploy.yml

Workflow Run:

Execution #102
Started:
Today
Status:
Success

Think of it like this:

Workflow
      │
      ▼
Workflow Run #1

Workflow
      │
      ▼
Workflow Run #2

Workflow
      │
      ▼
Workflow Run #3

One workflow can have thousands of runs.

Troubleshooting

Workflow Not Found

could not find any workflows named ...

Fix:

List workflows.

gh workflow list

Copy the exact name.

Missing Input

Required input 'environment'
not provided

Fix:

gh workflow view "Workflow Name" --yaml

Check required inputs.

Then run:

gh workflow run "Workflow Name" \
-f environment=testing

Invalid Choice

Provided value
not in allowed values

Fix:

Use one of the options defined inside:

workflow_dispatch:
  inputs:

Interview Questions

Q1. What is the difference between a workflow and a workflow run?

Answer

A workflow is the YAML definition stored in the repository.

A workflow run is one execution of that workflow.

Q2. Why is workflow_dispatch required?

Answer

workflow_dispatch enables manual execution of a workflow. Without it, gh workflow run cannot trigger the workflow.

Q3. How do you pass inputs to a manually triggered workflow?

Answer

Use the -f (or --field) option.

Example:

gh workflow run deploy.yml \
-f environment=production

Interview Questions

Q1. What is the difference between gh workflow and gh run?

Answer

  • gh workflow manages workflow definitions (list, view, trigger).
  • gh run manages workflow executions (list runs, inspect jobs, view logs, download artifacts).

Q2. How do you identify which job failed in a matrix workflow?

Answer

Run:

gh run view <RUN_ID> --json jobs

It displays every job in the matrix with its status and conclusion.

Q3. How do you troubleshoot a failed GitHub Actions workflow?

Answer

  1. List recent runs with gh run list.
  2. View the run using gh run view <RUN_ID>.
  3. Check failed logs using gh run view <RUN_ID> --log-failed.
  4. Review the failing job and rerun the workflow after fixing the issue.

Part 4A – gh api & gh gist

gh api

What is gh api?

gh api allows you to make raw GitHub REST API requests directly from your terminal.

Instead of opening the GitHub website, you can retrieve or update GitHub data using the GitHub API.

It is commonly used in:

  • DevOps automation
  • Shell scripts
  • CI/CD pipelines
  • Monitoring
  • Reporting

Syntax

gh api <endpoint>

Example:

gh api user

Get Your GitHub Profile

gh api user

Example Output

{
  "login": "alank8s-cloud-code",
  "name": "Alan",
  "public_repos": 12
}

List Your Repositories

gh api user/repos

View Repository Details

gh api repos/alank8s-cloud-code/my_portfolio

List Pull Requests

gh api repos/alank8s-cloud-code/my_portfolio/pulls

List Issues

gh api repos/alank8s-cloud-code/my_portfolio/issues

List Workflow Runs

gh api repos/alank8s-cloud-code/github-actions-practice/actions/runs

List Repository Secrets

gh api repos/alank8s-cloud-code/github-actions-practice/actions/secrets

Example Output

DATABASE_URL
AWS_ACCESS_KEY
DOCKER_USERNAME

Note: GitHub only returns the names of secrets, never their values.

Get Latest Release

gh api repos/alank8s-cloud-code/my_portfolio/releases/latest

List Collaborators

gh api repos/alank8s-cloud-code/my_portfolio/collaborators

Pretty Print JSON

Use jq to format JSON output.

gh api user | jq

Example

{
  "login": "alank8s-cloud-code",
  "followers": 20
}

Real DevOps Example 1

Check the latest workflow runs every morning.

gh api repos/alank8s-cloud-code/github-actions-practice/actions/runs

Real DevOps Example 2

Check whether production secrets exist.

gh api repos/alank8s-cloud-code/github-actions-practice/actions/secrets

Real DevOps Example 3

Generate a deployment report.

gh api repos/alank8s-cloud-code/my_portfolio/releases/latest

gh gist

What is a Gist?

A GitHub Gist is a lightweight Git repository used to share:

  • Scripts
  • YAML files
  • Docker Compose files
  • Terraform code
  • Notes
  • Configuration files

Think of it as a mini GitHub repository for small projects or code snippets.

Syntax

gh gist create <file>

Create a Public Gist

gh gist create deployment.yaml --public

Example Output

✓ Created public gist

https://gist.github.com/alank8s-cloud-code/abc1234567890abcdef

Add a Description

gh gist create deployment.yaml \
--public \
-d "Nginx Kubernetes Deployment"

What is -d?

-d stands for description.

It adds a short title or explanation to your Gist so others understand its purpose.

Create a Secret Gist

gh gist create backup.sh

Secret Gists are not listed on your public GitHub profile, but anyone with the link can access them.

List Your Gists

gh gist list

Example

ID           VISIBILITY
abc123456    public
xyz456789    secret

View a Gist

gh gist view abc123456

Open it in your browser:

gh gist view abc123456 --web

How Your Teammate Uses Your Gist

You create:

gh gist create deployment.yaml \
--public \
-d "Nginx Deployment"

GitHub returns:

https://gist.github.com/alank8s-cloud-code/abc1234567890abcdef

Share this link with your teammate.

They can:

  • View the code
  • Copy the code
  • Download the file
  • Clone the Gist

Clone the Gist

git clone https://gist.github.com/abc1234567890abcdef.git

Example

deployment.yaml

Deploy it:

kubectl apply -f deployment.yaml

Real DevOps Example 1

Share a Kubernetes deployment.

gh gist create deployment.yaml \
--public \
-d "Production Kubernetes Deployment"

Real DevOps Example 2

Share a Docker Compose file.

gh gist create docker-compose.yml \
--public \
-d "Jenkins Docker Compose"

Real DevOps Example 3

Share a GitHub Actions workflow.

gh gist create .github/workflows/ci.yml \
--public \
-d "CI Pipeline"

Real DevOps Example 4

Share a Bash script.

gh gist create backup.sh \
--public \
-d "Nightly Backup Script"

gh release

What is a Release?

A GitHub Release is a published version of your project.

It is typically used to distribute:

  • Application binaries
  • Docker image information
  • Source code snapshots
  • Release notes
  • Production versions

A release is usually created from a Git tag.

Example:

v1.0.0
v1.1.0
v2.0.0

Real DevOps Workflow

Developer
    │
    ▼
Code Complete
    │
    ▼
Create Git Tag
    │
    ▼
Push Tag
    │
    ▼
Create GitHub Release
    │
    ▼
Users Download Release

Create a Release

Syntax

gh release create <tag>

Example

gh release create v1.0.0 \
--title "Production Release v1.0.0" \
--notes "Initial production release."

Example Output

✓ Created release v1.0.0

Attach Files to a Release

Example:

gh release create v1.1.0 app.tar.gz \
--title "Application Release" \
--notes "Production build"

Uploaded file:

app.tar.gz

List Releases

gh release list

Example

v1.1.0
v1.0.0

View Release Details

gh release view v1.0.0

Open Release in Browser

gh release view v1.0.0 --web

Delete a Release

gh release delete v1.0.0

Real DevOps Example

Your CI/CD pipeline builds:

my-app.tar.gz

Publish it:

gh release create v2.0.0 my-app.tar.gz \
--title "Production Release" \
--notes "Security updates included."

Users can now download the release from GitHub.

gh alias

What is an Alias?

An alias is a shortcut for a GitHub CLI command.

Instead of typing long commands repeatedly, create a short command.

Create an Alias

Syntax

gh alias set <alias> "<command>"

Example 1

gh alias set prs "pr list"

Now run:

gh prs

Equivalent to:

gh pr list

Example 2

gh alias set runs "run list"

Use:

gh runs

Example 3

gh alias set issues "issue list"

Use:

gh issues

Example 4

gh alias set wf "workflow list"

Use:

gh wf

List Aliases

gh alias list

Example Output

prs: pr list
runs: run list
issues: issue list
wf: workflow list

Delete an Alias

gh alias delete prs

Real DevOps Example

Instead of typing:

gh workflow list

Every day, create:

gh alias set wf "workflow list"

Now simply run:

gh wf

gh search repos

What is gh search repos?

This command searches public GitHub repositories directly from your terminal.

Useful for finding:

  • Open-source projects
  • DevOps examples
  • Kubernetes manifests
  • Terraform modules
  • Docker examples
  • GitHub Actions workflows

Syntax

gh search repos "<keyword>"

Search Kubernetes Projects

gh search repos kubernetes

Search Docker Compose Examples

gh search repos "docker compose"

Search Terraform Projects

gh search repos "terraform aws"

Search GitHub Actions Examples

gh search repos "github-actions language:YAML"

Search Helm Charts

gh search repos "helm charts"

Search Jenkins Pipelines

gh search repos jenkinsfile

Search CI/CD Projects

gh search repos "ci cd"

Limit Results

gh search repos kubernetes --limit 5

Example Output

kubernetes/kubernetes
kubernetes/minikube
kubernetes/dashboard
kubernetes/website
helm/helm

Real DevOps Examples

Find Kubernetes Examples

gh search repos kubernetes --limit 10

gh search repos "terraform aws"

Interview Questions

Q1. What is the purpose of a GitHub Release?

Answer

A GitHub Release packages a specific version of a project, usually associated with a Git tag. It allows developers to publish release notes and attach build artifacts for users to download.

Q2. Why would you create GitHub CLI aliases?

Answer

Aliases save time by replacing long or frequently used commands with shorter custom commands, improving productivity.

Q3. How can gh search repos help a DevOps engineer?

Answer

It helps quickly discover open-source repositories, CI/CD examples, Kubernetes manifests, Terraform modules, Docker Compose projects, and other reusable resources directly from the terminal.
